BEFORE QUESTIONS / RAG 101

資料要先做好 準備

不是把一疊 PDF 直接丟給模型就結束

1蒐集可信文件公告、手冊、論文
2拆成可查片段Chunk / 文件區塊
3建立檢索索引Index + 中繼資料
有些系統會將文字轉成 Embedding（數值向量），用來找到語意相近的片段。
WIKI SOURCESS04 S0506 / 14
講者筆記：Embedding 是向量表示，不是判斷句子真假的神奇分數。Chunk 大小會影響檢索，但本課不討論具體參數。
AT QUESTION TIME / RAG 101

提問後的 三步流程

Retrieve → Augment → Generate

①Retrieve搜尋相關片段
②Augment把片段加入問題
③Generate模型根據資料作答
最重要的是：模型回答時，有機會使用取回的資料當作依據，而不是只靠訓練時留下的知識。

A CONCRETE EXAMPLE / RAG 101

假設有人問：
「加退選到哪一天？」

以下是虛構的教學情境，不是任何學校的實際公告

學生：這學期加退選的截止日是什麼時候？
檢索器：找到「本學期選課公告」中的截止日期欄位。
AI：依該公告的日期作答，並提供公告連結。

沒有找到公告？正確做法是說資料不足，而不是自行猜測日期。

SEARCH OPTIONS / RAG 101

怎麼決定 要找哪份資料？

索引可以支援不只一種檢索方式

Keyword

關鍵字

善於比對明確詞語、代碼或標題。

Vector

向量搜尋

使用 Embedding 的數值表示比對相近內容。

Hybrid

混合搜尋

結合不同檢索方式，提高找到所需內容的機會。

不需要只選一種；方法要依資料與問題測試。

WIKI SOURCESS03 S0509 / 14
講者筆記：避免把「向量搜尋」說成「永遠更精準」；文件只列出不同檢索模式。
KNOW THE LIMITS / RAG 101

有來源 ≠ 一定正確

RAG 仍可能發生三類錯誤

找錯資料

檢索沒有找到關鍵內容。

讀錯資料

回答把條件或結論講反。

用錯資料

資料過期，或超過使用者的閱讀權限。

所以不能只問「有沒有回答」，還要問「答案由哪份資料支持」。

WIKI SOURCESS03 S05 S0610 / 14
講者筆記：來源指出幻覺仍可能發生，權限也應在檢索層控制。
CHECK IN TWO PLACES / RAG 101

驗證要分成 兩個關卡

先查檢索，再查生成

GATE A

檢索品質

「找回來的片段真的有回答所需的資訊嗎？」

GATE B

答案忠實度

「答案中的重要說法，能被那些片段支持嗎？」

如果第一關就錯，就先修檢索，不必把整份答案重新生成。

COMPARISON / RAG 101

RAG 與 微調 不一樣

兩者可以搭配，但處理的問題不同

RAG

補上外部知識

適合需要特定文件、可更新的資料與可追蹤來源。

Fine-tuning

調整模型行為

偏向特定任務、輸出方式與行為上的調整。

不是「用了微調就不需要檢索」，也不是「RAG 可以取代所有訓練」。
